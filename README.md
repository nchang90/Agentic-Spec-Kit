# Agentic Spec Kit

A hands-on workshop repository for building software and Azure infrastructure
with [Spec Kit](https://github.com/github/spec-kit), GitHub Copilot, and
executable engineering policy.

The central idea is simple:

1. Write standing rules in a constitution.
2. Specify observable outcomes without choosing an implementation.
3. Plan the technology and architecture.
4. Generate dependency-ordered tasks.
5. Implement, verify, and converge the result back against the specification.

This repository makes that loop concrete with three labs, an Azure Verified
Modules (AVM) infrastructure example, and a verifier
that turns the infrastructure constitution into executable checks.

## Start here

| Path | Purpose | Azure cost |
|---|---|---:|

If this is your first time using Spec Kit, complete Lab 0 before attempting a
deployment lab.

## Repository map

```text

├── copilot-instructions.md    # Repository guidance for Copilot

.specify/

infra/                         # Root Terraform AVM reference configuration
lab/                           # Guided exercises, runbooks, and reference assets
```

The checked-in constitution is intentionally infrastructure-focused. Individual
application runbooks replace it on a scratch branch or in a separate workspace,
then restore it during cleanup.

- Node.js LTS
- the Spec Kit CLI

checklists. Do not deploy before reading the cost and teardown sections.

## Verify the AVM reference

The verifier checks module sourcing and pinning, identity, observability,
reversibility, formatting, and Terraform validation:

```bash
terraform -chdir=infra init -backend=false
node .github/scripts/verify-avm.mjs --dir infra --offline
```

Omit `--offline` to verify each module's supported inputs against the Terraform
Registry. No Azure resources are created by either command.

## Safety

- Never commit credentials, `.tfvars`, Terraform state, local databases, or
  `.azure/`.
- Always run the documented validation gate before deploying.
- Always tear down lab resources the same day.
- Preview cleanup paths explicitly; do not use broad `git clean -fd` commands in
  a working repository.
